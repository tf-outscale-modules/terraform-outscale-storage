## Why
A review of the released module found a secret landing in state, a tag precedence that lets callers override module-owned tags, and several validation and documentation gaps. All are fixed without removing or renaming an input or output, so the release is a **minor** (new `Name` tag on images and export tasks, new `check`); everything else is a fix.

## What Changes
| # | Issue | Decision | Breaking |
|---|-------|----------|----------|
| S1 | The export tasks put `osu_api_key.secret_key` in the resource, so it lands in state. Provider outscale 1.8 schema: `osu_export.osu_api_key.secret_key` of `outscale_image_export_task` and `outscale_snapshot_export_task` is a plain, non-sensitive, non-write-only attribute; there is no `*_wo` argument and no ephemeral alternative. | **Doc + `check`**. New `SECURITY.md` ("what lands in state" table, mitigation: dedicated least-privilege OSU key limited to the export bucket, rotation, encrypted state with restricted access). A `check "osu_api_key_in_state"` warns whenever an export task is planned. The inputs stay `sensitive` (not `ephemeral`, which cannot flow into a non-write-only argument). Future major: switch to a write-only argument when the provider offers one. | No |
| 2 | `volume_links.tags` is accepted but never used (`outscale_volume_link` has no tags) | **Doc fix**. Removing the attribute would break callers that set it; the description now states it is ignored and deprecated. Future major: remove it. | No |
| 3 | `var.tags` could override `Project`, `Environment`, `ManagedBy` | **Code fix**. `var.tags` is merged first, the three module tags win. Per-resource `tags` still win over everything (unchanged). Only configs that override these keys see an in-place tag update. | No (patch behaviour) |
| 4 | Images and export tasks have no `Name` tag | **Code fix**. `Name` = `image_name` for images, `<project>-<environment>-<key>` for export tasks; per-resource `tags` can override it (as for volumes and snapshots). In-place tag addition on existing resources. | No (minor) |
| 5 | `images` need neither `vm_id` nor `source_image_id` | **Code fix**. Validation rejects such an entry: the module exposes no other image source, so the request was invalid. | No |
| 6 | `project_name` has no validation | **Code fix**. Rejects blank names and names over 100 characters (they produced empty `Project` tags and malformed `Name` tags). Charset left open so no working name is rejected. | No for non-blank names |
| 7 | README links a `CHANGELOG.md` that does not exist; says `terraform fmt`/`terraform test` | **Doc fix**. The file is generated by git-cliff at release, so the link now points to the releases page; commands say `tofu`. | No |

State: no new input. The `secret_key` of the two OSU API key inputs already lands in state; it is now documented in `SECURITY.md`.

The `required_version` floor stays at 1.5, so no cross-variable validation is used.

## Capabilities
Modified: `module-contract` (common tags, project_name, export key in state), `images` (source validation, Name tag), `volumes` (volume link tags).
